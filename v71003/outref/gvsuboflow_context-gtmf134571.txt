# GT.M issues a GVSUBOFLOW error message with the length of the exceeded subscript, in certain cases it appends the string "..." indicating the subscript is incomplete. Previously, GT.M issued a less informative GVSUBOFLOW error message. (GTM-F134571)
# 

# Run routines that each generate a GVSUBOFLOW error. Expect the context message to include:
# 1. The length of the subscript and the max subscript length
# 2. The subscript to be truncated, with OR without '...'
# The routines cover these cases:
# 1. Simple subscript overflow that greatly exceeds max length
# 2. Short subscripts precede a long subscript
# 3. Short subscripts follow a long subscript
# 4-14. Simple subscript overflow at a variety of key sizes (1013-1023)
#    See the following discussions for details:
#    + https://gitlab.com/YottaDB/DB/YDBTest/-/merge_requests/2406#note_2672568670
#    + https://gitlab.com/YottaDB/DB/YDB/-/merge_requests/1847#note_3472432051
# Previously:
# 1. The subscript length and max would be omitted 
# 2. The ellipsis would be omitted and a '*' character would be emitted instead.
