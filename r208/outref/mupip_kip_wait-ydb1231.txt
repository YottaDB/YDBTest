#-----------------------------------------------------------------------------------------------#
# [#1231] MUPIP INTEG, FREEZE and BACKUP do not wait for an abandoned KILL                       #
#-----------------------------------------------------------------------------------------------#

# A KILL whose process terminated without running its cleanup leaves kill_in_prog set in the file
# header, and its own process id in the shared memory list of processes doing a KILL, with nothing
# left that can clear either. MUPIP INTEG waited a minute for that field in ss_initiate, or in
# region_freeze_main for a -noonline INTEG, and then another minute in mu_int_maps, so MUKILLIP,
# which it was going to issue either way, took two minutes to arrive. MUPIP FREEZE and MUPIP BACKUP
# waited a minute before failing with MUNOFINISH and before warning with BACKUPKILLIP respectively.
#
# The WBTEST_ABANDONEDKILL white box test case holds a process in phase II of a KILL, where
# kill_in_prog is set. This subtest terminates it there with SIGKILL, which the process cannot
# handle, so nothing of it runs again. Each stage times its command and compares the elapsed seconds
# against a limit instead of printing them, since the number itself is not reproducible.
#
# The INTEG output goes to a file rather than to this log. Stopping a KILL in its second phase
# leaves blocks marked busy that nothing references any more, and INTEG reports one DBLOCMBINC
# and DBMRKBUSY per bitmap and block involved, which is not a fixed number across the block sizes
# the test system chooses from. MUKILLIP is asserted out of that file; the rest of it is gzipped
# so that com/errors.csh does not read those messages as a failure.

# Stage 7 : kip_set_by_dse in a database created by an older release. The field was taken from the
# end of secshr_ops_array_filler, so an older file header can carry any bytes there, and a non-zero
# value would make every wait act as if a DSE-set kill_in_prog were in progress. Auto upgrade has to
# zero it once, and only once, so that a kill_in_prog that DSE sets later is still recognised after
# DSE exits. This is done for a V7 database, which db_auto_upgrade handles, and for a V6 database,
# which v6_db_auto_upgrade handles. Each is created by a random prior release, gets 0xDEADBEEF
# written over the field, and is then opened by the current release.
# Expected : kip_set_by_dse reads 0 after opening and is zeros on disk after close, then reads 1
# after DSE sets kill_in_prog and exits, and 0 after DSE clears it
# Before YDB#1231 : there is no kip_set_by_dse field, so offset^ydb1231 gets LVUNDEF and
# %PEEKBYNAME gets PBNINVALID
