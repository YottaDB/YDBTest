# [YDB#1356] $ZTRIGGER() and MUPIP TRIGGER reject a trigger whose subscript is a string too long to  #
# fit in a key                                                                                       #
#----------------------------------------------------------------------------------------------------#

# $ZTRIGGER() and MUPIP TRIGGER did not check the length of a string subscript in a trigger
# specification. The first update of the global loads the trigger, and gvtr_process_range() converts
# each subscript to the key form with mval2subsc(), which issued GVSUBOFLOW for a subscript too long
# to fit in a key. So every SET of the global failed with GVSUBOFLOW until the trigger was deleted. A
# Debug build failed an assert in stp_gcol_src.h instead. With the fix, $ZTRIGGER() and MUPIP TRIGGER
# reject such a trigger with "Subscript too long to fit in a key".
#
# The region has the largest possible key size (1019 bytes). A key whose only subscript is a string of
# n bytes has n + 5 bytes with a one character global name (and one more byte for each byte that is
# 0x00 or 0x01), so the longest string that fits in a key as the only subscript is 1014 bytes.
#
# Each stage runs in a new process. Without the fix, stages 1, 2, 4, 5, 7, 8, 10, 11, 13, 15, 16 and 18
# print FAIL (in a Debug build, the SET of ^a(1) in stages 1, 4 and 16, of ^b(1) in stage 8, of ^c(1) in
# stage 11 and of ^d(1) in stage 13 fails an assert in stp_gcol_src.h), and stages 3, 6, 9, 12, 14 and 17
# PASS.

# With the fix   : expect $ZTRIGGER to return 0 with "Subscript too long to fit in a key", and SET
