# [YDB#1294] Test a process loads the readline history file only when it reads from a terminal through readline     #
# With ydb_readline=1, a process used to dlopen libreadline and load (creating it if needed) its history file at    #
# startup, even when it could never use readline, e.g. with its input from a file or pipe, or a "yottadb -run" that #
# never enters direct mode. That took time in proportion to the size of the file, and issued a READLINEFILEPERM     #
# warning when the file could not be created. The history file is now loaded just before the first read through     #
# readline, i.e. at the first direct mode or DSE/LKE/MUPIP prompt on a terminal. This subtest verifies that:        #
#   1. yottadb -run with input from /dev/null does not create the history file                                      #
#   2. yottadb -direct with input from a pipe does not create the history file                                      #
#   3. LKE, DSE and MUPIP with input from a pipe do not create their history files                                  #
#   4. yottadb -run with input from /dev/null and an unwritable HOME issues no READLINEFILEPERM warning             #
#   5. yottadb -run from a terminal, that never enters direct mode, does not create the history file                #
#   6. yottadb -direct from a terminal creates the history file and saves the line typed at the prompt              #
#   7. LKE from a terminal creates its history file and saves the command typed at the prompt                       #
#   8. A call-in whose M code enters direct mode from a terminal does not create the history file, since a        #
#      call-in never uses readline                                                                                  #
#-------------------------------------------------------------------------------------------------------------------#
