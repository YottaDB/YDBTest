#-------------------------------------------------------------------------------------------------#
# [YDB#1306] glvn pool slots used inside XECUTE and other indirect frames are freed when the frame #
# ends, and do not replace the slot of a FOR in the frame they run in                              #
#-------------------------------------------------------------------------------------------------#

# SET @ref=..., $ORDER(@ref,-1) and a FOR over a subscripted or indirect control variable save the
# variable in a slot of the glvn pool. A slot is freed when the frame that took it ends, but an indirect
# frame (XECUTE, $ETRAP, $ZTRAP, a ZBREAK action, the $ZTIMEOUT vector, $ZINTERRUPT) started with the
# glvn pool state of the frame it runs in, and never freed its slots. So:
# - stages 1 and 2 : an error inside XECUTE while SET or $ORDER saved an indirect reference left its
#   slot allocated, so a process that repeated it grew without limit
# - stage 3 : the same for a FOR over a subscripted control variable in any of those indirect frames,
#   even without an error
# - stage 4 : such a FOR in an indirect frame took over the slot of a FOR at the same nesting level in
#   the frame it runs in, so the outer FOR stepped the inner control variable and never ended
#
# Stages 1 to 3 compare $ZREALSTOR after 1/10 of the runs and at the end. Before the fix, every leak
# made it grow by several hundred bytes per run, and a Debug build failed an assert in glvn_pool.c.
#
# Each stage runs in its own process.

# Stage 1 : an error inside XECUTE while $ORDER(@ref,-1) saves its indirect reference, 100000 times
#   xecute "set z=$order(@ref,-1)" with ref="x(undefv)" and undefv undefined, in a function with $ETRAP
# Command : $gtm_dist/mumps -run errxord^ydb1306
# Before the fix, a Release build grew $ZREALSTOR by about 44MB, so the line below was a WRONG line,
# and a Debug build failed an assert in glvn_pool.c, so the line below was missing
PASS : errxord : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000

# Stage 2 : an error inside XECUTE while SET @ref=... saves its indirect reference, 100000 times
#   xecute "set @ref=1" with ref="x(undefv)" and undefv undefined, in a function with $ETRAP
# Command : $gtm_dist/mumps -run errxset^ydb1306
# Before the fix, the same results as in stage 1
PASS : errxset : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000

# Stage 3 : a FOR over a subscripted control variable in each kind of indirect frame, without errors
#   for b(1)=1:1:2 set cnt=cnt+1
#   run 100000 times as XECUTE, $ETRAP, $ZTRAP and ZBREAK action code, and 5000 times as the $ZTIMEOUT
#   vector and as $ZINTERRUPT (sent to the process itself by $ZSIGPROC)
# Before the fix, a Release build grew $ZREALSTOR by about 51MB for 100000 runs and 3MB for 5000, so
# each line below was a WRONG line, and a Debug build failed an assert in glvn_pool.c, so each line
# below was missing
# Command : $gtm_dist/mumps -run forxec^ydb1306
PASS : forxec : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000
# Command : $gtm_dist/mumps -run foretrap^ydb1306
PASS : foretrap : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000
# Command : $gtm_dist/mumps -run forztrap^ydb1306
PASS : forztrap : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000
# Command : $gtm_dist/mumps -run forzbrk^ydb1306
PASS : forzbrk : $ZREALSTOR grew by less than 500000 bytes from run 10000 to run 100000
# Command : $gtm_dist/mumps -run forztout^ydb1306
PASS : forztout : $ZREALSTOR grew by less than 25000 bytes from run 500 to run 5000
# Command : $gtm_dist/mumps -run forzint^ydb1306
PASS : forzint : $ZREALSTOR grew by less than 25000 bytes from run 500 to run 5000

# Stage 4 : a FOR over a(1) whose body has a FOR over b(1) in an indirect frame (YDB#1318)
#   for a(1)=1:1:3 quit:cnt>20  xecute "for b(1)=1:1:2 set cnt=cnt+1"
#   also with indirect control variables, and with the inner FOR in the $ZTIMEOUT vector and in
#   $ZINTERRUPT, which interrupt the outer FOR
#   expect the inner FOR to run 6 times in all and the outer FOR to end with a(1)=3
# Before the fix, the outer FOR stepped b(1), which the inner FOR reset each time, so it never ended
# until "quit:cnt>20", and each line below was a WRONG line with the inner FOR run 22 times and a(1)=1
# Command : $gtm_dist/mumps -run nestxec^ydb1306
PASS : XECUTE : the inner FOR ran 6 times (expected 6) and the outer control variable ended at 3 (expected 3)
# Command : $gtm_dist/mumps -run nestind^ydb1306
PASS : XECUTE with indirect control variables : the inner FOR ran 6 times (expected 6) and the outer control variable ended at 3 (expected 3)
# Command : $gtm_dist/mumps -run nestztout^ydb1306
PASS : $ZTIMEOUT : the inner FOR ran 6 times (expected 6) and the outer control variable ended at 3 (expected 3)
# Command : $gtm_dist/mumps -run nestzint^ydb1306
PASS : $ZINTERRUPT : the inner FOR ran 6 times (expected 6) and the outer control variable ended at 3 (expected 3)

# Done
