#--------------------------------------------------------------------------------------------------#
# [#1143] The SEARCH_INDEX_SIZE and SEARCH_INDEX_SLOTS global directory segment characteristics    #
#--------------------------------------------------------------------------------------------------#

# 0 means two different things in a global directory, and getting them the wrong way round is the
# mistake this subtest exists to catch. SEARCH_INDEX_SIZE=0 means CHOOSE FOR ME, so a database made
# from it has search indexes ON at a quarter of the block size. SEARCH_INDEX_SLOTS=0 means OFF, since
# no slots is no search index. GDE SHOW displays the two as AUTO and OFF.

# This subtest drives GDE and MUPIP CREATE directly rather than through dbcreate.csh, because what is
# under test is the path from a global directory characteristic to a created file header.
# 1. GDE defaults : SIDX unspecified and SISL 1024, shown as AUTO and 1024
# change -segment DEFAULT -block_size=4096 -file=mumps.dat
SIDX=AUTO SISL=1024 : as expected
# mupip create >& create1.out
DEFAULT : Search Index Size 1024 Search Index Slots 1024 : as expected

# and the created database is ON, sized at a quarter of the 4096 byte block size

# 2. SEARCH_INDEX_SLOTS=0 turns it OFF. GDE shows OFF, and the created file header reads 0 and 0.
# The size named alongside it is deliberately non-zero, to show the slot count is what decides.
# change -segment DEFAULT -block_size=4096 -search_index_size=2048 -search_index_slots=0 -file=mumps.dat
SIDX=2048 SISL=OFF : as expected
# mupip create >& create2.out
DEFAULT : Search Index Size 0 Search Index Slots 0 : as expected

# 3. A named size and slot count both come through, with the count rounded up to a power of two
# change -segment DEFAULT -block_size=4096 -search_index_size=2048 -search_index_slots=5000 -file=mumps.dat
SIDX=2048 SISL=5000 : as expected
# mupip create >& create3.out
DEFAULT : Search Index Size 2048 Search Index Slots 8192 : as expected

# 4. A size below the minimum is raised to it, and one above this block size's ceiling is clamped,
# so a created database can never hold a value MUPIP SET would go on to refuse
# change -segment DEFAULT -block_size=4096 -search_index_size=8 -file=mumps.dat
# mupip create >& create4.out
DEFAULT : Search Index Size 128 Search Index Slots 1024 : as expected
# change -segment DEFAULT -block_size=4096 -search_index_size=8192 -file=mumps.dat
# mupip create >& create5.out
DEFAULT : Search Index Size 4088 Search Index Slots 1024 : as expected

# 5. GDE refuses a negative count, which is why 0 has to carry the OFF meaning : GDE cannot
# emit a negative that its own SHOW -COMMAND output would parse back, so there is no second
# sentinel available alongside AUTO.
# change -segment DEFAULT -search_index_slots=-1
----------
Error VALUEBAD seen in gde6.out as expected:
%GDE-E-VALUEBAD, - is not a valid number
----------

# 6. The global directory format label moves because the segment gained these two characteristics.
# A global directory written by a random prior release carries a format below 016; opening it with
# this release and exiting converts it to 016 or above. The exact numbers depend on which release
# the test picked, so only the two sides of 16 are checked.
# mumps -run GDE exit >& gde8.out
global directory format moved from below 016 to 016 or above, as expected

# 7. -NOSEARCH_INDEX is the readable way to say the same thing as SEARCH_INDEX_SLOTS=0, and
# -SEARCH_INDEX turns it back on. Neither is stored : both are translated into the slot count,
# so a global directory still holds only the two numbers and SHOW round-trips through them.
# change -segment DEFAULT -block_size=4096 -nosearch_index -file=mumps.dat
SIDX=AUTO SISL=OFF : as expected
# mupip create >& create9.out
DEFAULT : Search Index Size 0 Search Index Slots 0 : as expected
# and back on, which restores the default count rather than inventing one, and gives a
# created database an enabled file header again, the mirror of the 0 and 0 just above
# change -segment DEFAULT -search_index
SIDX=AUTO SISL=1024 : as expected
# mupip create >& create10.out
DEFAULT : Search Index Size 1024 Search Index Slots 1024 : as expected

# 8. -SEARCH_INDEX supplies the default count only when the command does not name one. This
# command names 4096, so the segment ends up with 4096 rather than the 1024 the stage above
# got, where -SEARCH_INDEX was the only thing named.
# change -segment DEFAULT -search_index -search_index_slots=4096
SIDX=AUTO SISL=4096 : as expected

# 9. -SEARCH_INDEX=0 is now REFUSED rather than silently meaning AUTO. Before the qualifier
# existed, -SEARCH_INDEX abbreviated to SEARCH_INDEX_SIZE and 0 there means choose-for-me, so
# the natural way to ask for off quietly did nothing at all.
# change -segment DEFAULT -search_index=0
----------
Error NOVALUE seen in gde12.out as expected:
%GDE-E-NOVALUE, Qualifier SEARCH_INDEX does not take a value
----------

# 10. The default size is a QUARTER OF THE BLOCK SIZE, not a fixed 1024. Every other stage here
# uses a 4096 byte block, where a quarter happens to be 1024, so on its own that proves nothing.
# These block sizes each have a different quarter.
# change -segment DEFAULT -block_size=1024 -file=mumps.dat
# mupip create >& create.bs1024.out
block size 1024 : DEFAULT : Search Index Size 256 Search Index Slots 4096 : as expected
# change -segment DEFAULT -block_size=2048 -file=mumps.dat
# mupip create >& create.bs2048.out
block size 2048 : DEFAULT : Search Index Size 512 Search Index Slots 4096 : as expected
# change -segment DEFAULT -block_size=8192 -file=mumps.dat
# mupip create >& create.bs8192.out
block size 8192 : DEFAULT : Search Index Size 2048 Search Index Slots 4096 : as expected
# change -segment DEFAULT -block_size=16384 -file=mumps.dat
# mupip create >& create.bs16384.out
block size 16384 : DEFAULT : Search Index Size 4096 Search Index Slots 4096 : as expected
# 1024/4=256, 2048/4=512, 8192/4=2048, 16384/4=4096, each rounded up to a multiple of 8 and
# held within the 128 minimum and the ceiling of 8192 or 8 less than the block size.
