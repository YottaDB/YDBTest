# [YDB#1383] [YDB#1302] A TP restart or a ZGOTO that abandons a LOCK command makes the next    #
# lock command issue BADLOCKNEST, and a LOCK that resumes after a transaction or an error in an #
# extrinsic that a lock name calls terminates with a SIG-11 or does not acquire every name      #
#----------------------------------------------------------------------------------------------#

# While a LOCK is processed, lks_this_cmd counts its names and the trans flag of each name is set.
# A TP restart from inside the LOCK resumes at the outermost TSTART, so the LOCK never completes, but
# the restart left lks_this_cmd and the flags set. The next lock command that starts with op_lkinit()
# (LOCK +, LOCK -, ZALLOCATE, ZDEALLOCATE, and the simpleAPI ydb_lock_incr_s() and ydb_lock_decr_s())
# then issued BADLOCKNEST. A ZGOTO out of an extrinsic that a lock name calls abandons the LOCK the same
# way. And a LOCK whose lock name calls an extrinsic resumes when the extrinsic returns: a transaction
# in the extrinsic deleted the list entries of the names that the LOCK had not yet acquired, which
# terminated the process with a SIG-11 when the LOCK resumed, and an error that the $ETRAP of the
# extrinsic handles cleared those names (YDB#1302), so the LOCK did not acquire them.
#
# Each stage runs in a new process, with ^x in region DEFAULT and ^a in region AREG. The transaction
# restarts with TRESTART until the final retry, where the process holds crit on DEFAULT. There, a
# LOCK of ^x and ^a has to open region AREG, and opening a region while holding crit restarts the
# transaction. Each stage checks the transaction restarted this way, then runs its command as the
# first lock command of the restarted try, and checks the locks the process holds after TCOMMIT.

# Stage 1 : LOCK +(^x,^a) after the restart
# Command : $gtm_dist/mumps -run lockcmd^ydb1383 'lock +(^x,^a)|^a=1,^x=1|'
# Before the fix : BADLOCKNEST from LOCK +(^x,^a)
# With the fix   : expect no error, and the process to hold ^a and ^x at level 1
PASS : the transaction restarted from inside LOCK +(^x,^a) in the final retry
PASS : lock +(^x,^a) after the restart did not issue an error
PASS : the process holds ^a=1,^x=1
PASS : another process finds ^a held
PASS : another process finds ^x held

# Stage 2 : LOCK +^x before TSTART, then LOCK +^x after the restart. The interrupted LOCK named ^x,
#           so it set the trans flag of ^x, which was already locked.
# Command : $gtm_dist/mumps -run lockcmd^ydb1383 'lock +^x|^x=2|lock +^x'
# Before the fix : BADLOCKNEST from LOCK +^x
# With the fix   : expect no error, and the process to hold ^x at level 2. If the restart reset
#                  lks_this_cmd but left the trans flag of ^x set, LOCK +^x would not count ^x, and
#                  ^x would stay at level 1.
PASS : the transaction restarted from inside LOCK +(^x,^a) in the final retry
PASS : lock +^x after the restart did not issue an error
PASS : the process holds ^x=2
PASS : another process finds ^x held
