# [YDB#1287] MUPIP LOAD does not read past the end of a ZWR record whose key is cut short            #
#----------------------------------------------------------------------------------------------------#

# zwrkeyvallen() finds the key of a ZWR record for MUPIP LOAD. After a $, a closing " or a ) in the key,
# it read the next one to three bytes without checking them against the length of the record, and it
# scanned the ,<offset>,<length>) part of a $ze(...) record until it found a ) wherever that was.
# str2gvargs(), which then turns the key into a global reference, read past its end in the same way.
# MUPIP LOAD reads every line into the same buffer, so on a record whose key is cut short those reads
# found bytes left over from an earlier, longer line. The error LOAD reported, or whether it took the
# key as complete, then depended on those bytes. A dbg build failed an assert in one of the two instead.
#
# For each of 4 records, and each length that cuts the record within its key, the cut copy is loaded
# once after the full record and once after a filler record of the same length. Without the fix, the
# two loads of most cuts report different errors, as the error quotes bytes past the end of the cut.
