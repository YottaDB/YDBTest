#----------------------------------------------------------------------------------------------------#
# [YDB#1348] WRITE /mnemonic to a SOCKET device accepts BLOCK only as the whole mnemonic, and does   #
# not read past the end of the "BLOCK" literal                                                       #
#----------------------------------------------------------------------------------------------------#

# WRITE /mnemonic to a SOCKET device checked for BLOCK with memcmp() using the length of the mnemonic
# in the WRITE. A mnemonic longer than BLOCK made memcmp() read past the end of the literal "BLOCK"
# (which an ASAN build reports as a global-buffer-overflow), and any prefix of BLOCK was accepted as
# BLOCK. The mnemonic now has to be BLOCK (in any case), as LISTEN, WAIT, PASS, ACCEPT and TLS already
# have to be the whole mnemonic, and any other mnemonic issues INVCTLMNE.
# Each stage does its WRITE to a listening socket in a new process and prints PASS or WRONG.

# Stage 1 : WRITE /BLOCKG121, a mnemonic that starts with BLOCK and is longer than it
# Before the fix : INVCTLMNE too, but memcmp() read past the end of "BLOCK", which an ASAN build
#                  reported as a global-buffer-overflow, terminating the process
# With the fix   : expect INVCTLMNE
# Command : $gtm_dist/mumps -run long^ydb1348
PASS : WRITE /BLOCKG121 issued INVCTLMNE

# Stage 2 : WRITE /B("OFF"), the 1-character prefix of BLOCK
# Before the fix : taken as WRITE /BLOCK("OFF"), which issues SOCKBLOCKERR on a listening socket, so
#                  the line below was a WRONG line
# With the fix   : expect INVCTLMNE
# Command : $gtm_dist/mumps -run b^ydb1348
PASS : WRITE /B("OFF") issued INVCTLMNE

# Stage 3 : WRITE /BLO("CLEAR"), a 3-character prefix of BLOCK
# Before the fix : taken as WRITE /BLOCK("CLEAR"), with no error, so the line below was a WRONG line
# With the fix   : expect INVCTLMNE
# Command : $gtm_dist/mumps -run blo^ydb1348
PASS : WRITE /BLO("CLEAR") issued INVCTLMNE

# Stage 4 : WRITE /BLOCKS("CLEAR"), BLOCK followed by one more character
# Before the fix : the same output (this stage is a control)
# With the fix   : expect INVCTLMNE
# Command : $gtm_dist/mumps -run blocks^ydb1348
PASS : WRITE /BLOCKS("CLEAR") issued INVCTLMNE

# Stage 5 : WRITE /BLOCK("CLEAR") and WRITE /block("CLEAR")
# Before the fix : the same output (this stage is a control)
# With the fix   : expect no error for both
# Command : $gtm_dist/mumps -run block^ydb1348
PASS : WRITE /BLOCK("CLEAR") issued no error
PASS : WRITE /block("CLEAR") issued no error

# Done
