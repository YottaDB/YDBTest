# One slot for the whole database is legal, and is the worst case for the slot scheme: every
# index block maps to slot 0, so each one displaces the last. A search whose slot holds another
# block's index recognizes that from the block number in the stamp and walks the block the
# ordinary way, so the answers must be identical here too. The MM subtest covers the same case
# for MM, and this is its BG counterpart : the two access methods reach their slots by the same
# mask, so a fault in that arithmetic would show on either, but only BG displaces a slot from
# phase 2 of commit, outside crit, which MM never does.
