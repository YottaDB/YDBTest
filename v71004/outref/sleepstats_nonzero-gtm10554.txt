# ********************************************************************************************
# GTM-10554 - Test the following release note
# ********************************************************************************************
# 
# Release note (from http://tinco.pair.com/bhaskar/gtm/doc/articles/GTM_V7.1-004_Release_Notes.html#GTM-DE1959410554)
# 
# GT.M includes six additional counters tracking milliseconds of time slept while waiting on another process to finish a task. The counters are available as part of all forms of GVSTATs, and have the following mnemonics and descriptions:
# 
# JCS - milliseconds of time slept in crit waiting for another process to finish a write into the journal file.
# JNS - milliseconds of time slept outside of crit waiting for another process to finish a write into the journal file.
# WPCS - milliseconds of time slept in crit waiting for another process to finish flushing a block to disk.
# RCS - milliseconds of time slept in crit waiting for another process to finish reading in a block from disk.
# WFCS - milliseconds of time slept in crit while performing a flush of one or more blocks to disk, usually in an epoch.
# GCS - milliseconds of time slept in crit while acquiring a global buffer and waiting for another process to finish writing a block to disk.
# 
# These counters can help identify the cause of performance degradation. High values per second can indicate I/O throughput issues that are forcing GT.M to perform excessive coordination activity. (GTM-10554)
# 

# A counter increases only while a process sleeps because another process is in the middle of a write or a read.
# So each stage starts a "holder" process with a white-box test case that makes the holder sleep for 10 seconds
# in the middle of a write (142 = WBTEST_JNL_WRITE_HANG for the journal file, 143 = WBTEST_DB_WRITE_HANG for
# the database file), and then runs a "waiter" that needs what the holder owns. The waiter has to sleep until
# the holder is done, so the counter of that kind of sleep has to be 1000 (milliseconds) or more afterwards.
# This subtest covers JNS, JCS, WPCS and WFCS. RCS and GCS are not covered as there is no white-box test case
# that makes a process sleep in the middle of a block read, or between the end of a block write and the
# release of the global buffer.

# Stage 1 : JNS. The holder sleeps in a write to the journal file (outside crit).
# The waiter commits a TP transaction, which hardens the journal file after crit is released.
# Holder process is in the white-box sleep
JNS is 1000 or more : PASS

# Stage 2 : JCS. The holder sleeps in a write to the journal file (outside crit).
# The waiter runs VIEW "JNLFLUSH", which writes the journal buffer to the journal file while holding crit.
# Holder process is in the white-box sleep
JCS is 1000 or more : PASS

# Stage 3 : WPCS. The holder sleeps in a write of a global buffer to the database file.
# The waiter updates every node that the holder has set, so one of the updates needs that global buffer.
# Holder process is in the white-box sleep
WPCS is 1000 or more : PASS

# Stage 4 : WFCS. The holder sleeps in a write of a global buffer to the database file.
# The waiter is DSE BUFFER_FLUSH, which waits in crit for processes that are writing global buffers.
# DSE is a separate process, so this stage uses the counter that all processes share, from $VIEW("GVSTATS").
# Holder process is in the white-box sleep
WFCS increase is 1000 or more : PASS
